# LogForge Desktop

LogForge Desktop is the native desktop application wrapper for the LogForge self-hosted log management platform. Built with Electron, it packages the entire LogForge frontend into an installable app for macOS, Windows, and Linux — no browser required.

The frontend is embedded directly inside the app bundle at build time. The only external dependency is your own running **LogForge backend** instance.

## Architecture

```
logforge-desktop/
├── electron/
│   ├── main.js          # Electron main process
│   └── preload.js       # Context bridge — exposes window.electronAPI
├── assets/
│   ├── icon.png         # App icon — 1024×1024px PNG (source for all platforms)
│   └── entitlements.mac.plist  # macOS hardened runtime entitlements
├── dist/                # Generated installers (git-ignored)
├── package.json
└── README.md

../logforge-frontend/    # Must exist at this relative path
└── build/               # Generated by yarn build in logforge-frontend
```

The Electron app loads the frontend from `resources/frontend/index.html` inside the app bundle (production) or from `http://localhost:3000` (development). The frontend uses `HashRouter` when running inside Electron so that navigation works correctly with the `file://` protocol.

`window.electronAPI.isElectron` is exposed via the preload script and used by the frontend to show the backend URL configuration button.

## Project Structure

`logforge-desktop` and `logforge-frontend` live in **separate git repositories** but must be placed as **siblings inside the same parent directory** on your machine. They do not need to share a monorepo — the only requirement is the relative path.

```
any-folder/               ← parent directory (name doesn't matter)
├── logforge-frontend/    ← cloned from its own repository
└── logforge-desktop/     ← cloned from its own repository
```

The electron-builder config references `../logforge-frontend/build` as a relative path to embed the frontend into the app bundle at build time. As long as both repos are cloned side by side, everything works regardless of how they are hosted or versioned.

## Development

Run the app locally against the frontend dev server.

**Step 1 — Start the frontend dev server**

```bash
cd ../logforge-frontend
yarn install   # first time only
yarn start     # starts on http://localhost:3000
```

**Step 2 — Launch Electron** (in a second terminal, once the frontend is ready)

```bash
cd logforge-desktop
yarn install   # first time only
yarn dev
```

The DevTools open automatically in detached mode. Hot-reload works — changes in `logforge-frontend/src` are reflected live inside Electron.

## Building for Production

All build commands automatically trigger `yarn build` in `logforge-frontend` first, then package the Electron app.

### Install dependencies (once)

```bash
cd logforge-desktop
yarn install
```

---

### macOS — DMG

Produces a universal `.dmg` installer with two architecture variants: **x64** (Intel) and **arm64** (Apple Silicon).

```bash
yarn dist:mac
```

**Output:**
```
dist/
├── LogForge-0.2.0.dmg          # Universal installer
├── LogForge-0.2.0-arm64.dmg    # Apple Silicon specific (if built separately)
└── mac/
    └── LogForge.app            # Extracted app bundle
```

**Installation:**
1. Open the `.dmg` file
2. Drag `LogForge.app` to the `/Applications` folder
3. On first launch, right-click → Open (required once if the app is not notarized)

**Requirements:**
- Must be built on **macOS**
- Xcode Command Line Tools must be installed: `xcode-select --install`
- The `entitlements.mac.plist` file must be present in `assets/` (already included)

**Note on Gatekeeper:** The build is configured with `hardenedRuntime: true` and `gatekeeperAssess: false`. Without Apple Developer ID code signing and notarization, macOS will show a warning on first launch. To bypass it: right-click the app → Open → Open. This is a one-time step for unsigned builds.

To sign and notarize (optional, removes the warning), set these environment variables before building:

```bash
export CSC_LINK="path/to/certificate.p12"
export CSC_KEY_PASSWORD="your_cert_password"
export APPLE_ID="your@apple.id"
export APPLE_APP_SPECIFIC_PASSWORD="xxxx-xxxx-xxxx-xxxx"
export APPLE_TEAM_ID="YOUR_TEAM_ID"

yarn dist:mac
```

### Windows — EXE

Produces an NSIS installer (`.exe`) for **x64** Windows.

```bash
yarn dist:win
```

**Output:**
```
dist/
└── LogForge Setup 0.2.0.exe    # NSIS installer
```

**Installation:**
1. Run `LogForge Setup 0.2.0.exe`
2. The installer lets the user choose the installation directory
3. Creates a desktop shortcut and a Start Menu entry

**Requirements:**
- Can be built on **macOS or Linux** using Wine (auto-downloaded by electron-builder), or natively on **Windows**
- Building natively on Windows gives the most reliable result

**Note on SmartScreen:** Windows may show a SmartScreen warning for unsigned executables. To bypass it: click "More info" → "Run anyway". To remove the warning permanently, the `.exe` must be signed with a Code Signing certificate (EV certificate recommended for SmartScreen reputation).

### Linux — AppImage / DEB

Two formats are available for Linux:

| Format | Command | Best for |
|---|---|---|
| AppImage only | `yarn dist:linux:appimage` | Universal, no install needed |
| DEB only | `yarn dist:linux:deb` | Ubuntu / Debian (native package) |
| Both | `yarn dist:linux` | Distribute both at once |

**Output:**
```
dist/
├── LogForge-0.2.0.AppImage       # Portable — runs on any x64 Linux
└── LogForge-0.2.0.amd64.deb      # Debian/Ubuntu package
```

**AppImage usage:**
```bash
# Make executable (first time only)
chmod +x LogForge-0.2.0.AppImage

# Run
./LogForge-0.2.0.AppImage
```

> **Note:** AppImage requires FUSE on some systems. If you get a FUSE error, either install it (`sudo apt install libfuse2`) or use the `.deb` instead.

**DEB installation (Ubuntu/Debian):**
```bash
sudo dpkg -i LogForge-0.2.0.amd64.deb
```

The app appears automatically in the application menu after installation.

**Requirements:**
- Must be built on **Linux** for best compatibility
- Can also be built on macOS (cross-compile), but native Linux build is recommended

---

### All platforms at once

```bash
yarn dist:all
```

Packages for all three platforms in a single command (macOS DMG, Windows EXE, Linux AppImage + DEB). Automatically builds the frontend first.

Best run in a CI environment with all platform tools available.

## Backend Configuration

LogForge Desktop does **not** require the frontend to be deployed anywhere. The entire UI is bundled inside the app. The only external service needed is your **LogForge backend**.

When the app is running inside Electron, a small server icon button appears in the **bottom-right corner of the login screen**. Click it to open the backend configuration modal:

1. Enter your backend URL (e.g., `http://192.168.1.10:8000` or `https://logs.yourcompany.com`)
2. Click **Test connection** — the app pings `/api/health` to verify the backend is reachable
3. Click **Save & Reload** — the URL is persisted in `localStorage` and the app reloads

The configured URL is used for all API calls and WebSocket connections. It persists across app restarts.

**Default value:** `http://localhost:8000` (reads `REACT_APP_BACKEND_URL` env var if set at build time, otherwise falls back to localhost).

## Assets

| File | Required | Description |
|---|---|---|
| `assets/icon.png` | Yes | 1024×1024px PNG — source icon for all platforms. electron-builder auto-converts to `.icns` (Mac) and `.ico` (Windows). |
| `assets/entitlements.mac.plist` | Yes (Mac build) | Hardened runtime entitlements. Required for `hardenedRuntime: true`. |
| `assets/dmg-background.png` | No | Custom DMG window background. 540×380px PNG. If absent, default white background is used. |

To update the app icon, replace `assets/icon.png` with a new 1024×1024px PNG and rebuild.

## Cross-platform Build Notes

| Build target | macOS host | Windows host | Linux host |
|---|---|---|---|
| macOS DMG | Native | Not supported | Not supported |
| Windows EXE | Via Wine (auto) | Native | Via Wine (auto) |
| Linux AppImage | Via cross-compile | Not supported | Native |

**Recommendation:** use a CI/CD pipeline with a matrix strategy to build each platform natively.

**Example GitHub Actions matrix:**

```yaml
jobs:
  build:
    strategy:
      matrix:
        include:
          - os: macos-latest
            script: dist:mac
          - os: windows-latest
            script: dist:win
          - os: ubuntu-latest
            script: dist:linux
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: yarn install
        working-directory: logforge-desktop
      - run: yarn ${{ matrix.script }}
        working-directory: logforge-desktop
      - uses: actions/upload-artifact@v4
        with:
          name: logforge-${{ matrix.os }}
          path: logforge-desktop/dist/
```

## Troubleshooting

**The app opens a blank white screen**

The frontend build is missing or the path is wrong. Run:
```bash
cd ../logforge-frontend && yarn build
```
Then relaunch the app.

**`Error: Cannot find module` on `yarn dev`**

Dependencies are not installed. Run:
```bash
cd logforge-desktop && yarn install
```

**macOS: "LogForge is damaged and can't be opened"**

This happens with unsigned builds downloaded from the internet. Run:
```bash
xattr -cr /Applications/LogForge.app
```
Then relaunch.

**macOS build fails with entitlements error**

Make sure `assets/entitlements.mac.plist` exists and Xcode Command Line Tools are installed:
```bash
xcode-select --install
```

**Windows build on macOS fails**

electron-builder will attempt to download Wine automatically. If it fails, install Wine manually:
```bash
brew install --cask wine-stable
```

**`ENOENT: ../logforge-frontend/build`**

The frontend has never been built. Run:
```bash
cd ../logforge-frontend && yarn build
```

**Backend connection fails in the app**

- Verify the backend is running and accessible from the machine running the app
- Make sure the URL has no trailing slash
- Check that the backend's CORS configuration allows the Electron origin
- Use the Test connection button — it pings `/api/health` and shows the HTTP status or the error message
